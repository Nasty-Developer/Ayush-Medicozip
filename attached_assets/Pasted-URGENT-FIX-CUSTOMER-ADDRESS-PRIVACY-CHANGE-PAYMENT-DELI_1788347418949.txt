1. CRITICAL BUG — CUSTOMER ADDRESSES ARE SHARED
==================================================

CURRENT BUG:

When Customer A saves an address, that address is being stored/shared in a way that causes another customer to see Customer A's address.

THIS MUST NEVER HAPPEN.

Customer addresses must be PRIVATE to that customer.

For the current implementation, saved customer addresses should be stored CLIENT-SIDE only.

Use the existing browser/client-side storage mechanism appropriately, such as customer-scoped localStorage/state.

IMPORTANT:

Customer A:
→ saves Address A

Customer B:
→ must NOT see Address A

Customer B:
→ sees only Customer B's own saved addresses.

Do NOT use one global localStorage key that exposes the same address list to every customer.

If localStorage is used, scope the saved addresses by the authenticated customer's unique Firebase UID.

Example concept:

savedAddresses_${firebaseUser.uid}

NOT:

savedAddresses

Do not use a shared global address record for customer saved addresses.

==================================================
2. ADMIN MUST SEE THE ADDRESS FOR AN ORDER
==================================================

There is an important distinction:

SAVED CUSTOMER ADDRESSES:
→ private/client-side

ADDRESS ATTACHED TO A PLACED ORDER:
→ must be stored with that specific order

ADMIN:
→ must be able to see the delivery address belonging to that specific order.

Therefore:

Customer A saved addresses
→ private to Customer A

Customer A places Order #123
→ selected delivery address is copied into Order #123

Admin opens Order #123
→ admin sees the delivery address for Order #123

Customer B:
→ cannot see Customer A's saved addresses
→ cannot see Customer A's order address

Do NOT expose the customer's entire saved-address list to the admin.

Only the address actually associated with the order should be available to the admin for fulfillment.
