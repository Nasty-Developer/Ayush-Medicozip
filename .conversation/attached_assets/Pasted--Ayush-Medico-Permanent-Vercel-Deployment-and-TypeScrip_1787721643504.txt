# STEP 5: FIX THE BACKEND DEPLOYMENT MODEL

The repository already has:

```text

```

which uses esbuild and starts from:

```text
artifacts/api-server/src/app.ts
```

Keep and improve this architecture rather than replacing it unnecessarily.

The intended flow is:

```text
artifacts/api-server/src/app.ts
        ↓
      esbuild
        ↓
api/.vercel-build/app.mjs
        ↓
Vercel API Function
```

The deployed function must NOT depend on:

```text
@workspace/api-zod/src/index.ts
@workspace/db/src/index.ts
```

being present as runtime TypeScript source.

Workspace packages that are safe to bundle should be bundled into the API.

Runtime external dependencies should remain external only when they are guaranteed to exist in the Vercel deployment environment.

Do not leave a production dependency pointing at a workspace `.ts` source file unless there is a proven and intentional Vercel runtime mechanism for it.
